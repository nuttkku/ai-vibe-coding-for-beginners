## Git Desktop คืออะไร?

ลองนึกภาพว่า Git คือ **ระบบ Save Game** ในเกมวิดีโอเกม:
- ทุกครั้งที่ Commit = กดปุ่ม Save
- ถ้างานเสียหาย = โหลด Save เก่ากลับมาได้
- เห็นประวัติทุก Save ที่เคยทำ

**GitHub Desktop** คือหน้าต่างกราฟิก (GUI) ที่ทำให้เราใช้ Git ได้โดยไม่ต้องพิมพ์คำสั่งเลย

## ส่วนที่ 1: สร้าง Repository จากโฟลเดอร์ที่มีอยู่

**Repository** = โฟลเดอร์ที่ Git คอยติดตามดูแลอยู่

**1.1 เปิด GitHub Desktop**
1. เปิดโปรแกรม GitHub Desktop

**1.2 เพิ่มโฟลเดอร์ my-first-webpage**
1. คลิก **File** → **Add Local Repository**
   - หรือกด `Ctrl + O`
2. คลิกปุ่ม **"Choose..."** แล้วเลือกโฟลเดอร์ `my-first-webpage`
3. โปรแกรมอาจแจ้งว่า "This directory does not appear to be a Git repository"
4. คลิก **"Create a repository"** (ไม่ใช่ Cancel!)
5. หน้าต่างสร้าง Repository จะเปิดขึ้น:
   - **Name:** `my-first-webpage` (จะถูกกรอกมาให้แล้ว)
   - **Local path:** โฟลเดอร์ที่เราเลือก
   - **Initialize this repository with a README:** ไม่ต้องติ๊ก (เรามีไฟล์แล้ว)
6. คลิก **"Create Repository"**

**ผลที่ควรเห็น:** หน้าต่าง GitHub Desktop แสดงชื่อ Repository ที่มุมบนซ้าย

## ส่วนที่ 2: ทำความเข้าใจหน้าตา GitHub Desktop

```
┌──────────────────────────────────────────────────────┐
│ GitHub Desktop                                        │
├───────────────────┬──────────────────────────────────┤
│ Changes (1)       │  index.html                      │ ← ไฟล์ที่เปลี่ยน
│ ─────────────────│  ─────────────────────────────── │
│ ☑ index.html     │  + <html>                         │ ← สีเขียว = เพิ่มใหม่
│                   │  + <head>...</head>               │
│                   │  + <body>...</body>               │
│                   │                                   │
├───────────────────┴──────────────────────────────────┤
│ Summary: [พิมพ์ชื่อ Commit ที่นี่]          [Commit]  │
└──────────────────────────────────────────────────────┘
```

| ส่วน | ความหมาย |
|---|---|
| **Changes** | รายการไฟล์ที่มีการเปลี่ยนแปลง ยังไม่ได้ Save |
| **สีเขียว (+)** | ไฟล์ใหม่ หรือบรรทัดที่เพิ่มมา |
| **สีแดง (-)** | บรรทัดที่ถูกลบออก |
| **Summary** | ชื่อของ Commit (เหมือนชื่อ Save) |
| **History** | ดูประวัติ Commit ทั้งหมด |

## ส่วนที่ 3: Commit งานชิ้นแรก

**3.1 ตรวจสอบไฟล์ใน Changes**
1. ด้านซ้ายจะเห็น `index.html` อยู่ใน Changes
2. คลิกที่ `index.html` เพื่อดูรายละเอียดการเปลี่ยนแปลง
3. ทุกบรรทัดที่เป็นสีเขียว = โค้ดที่จะถูก Save

**3.2 เขียน Commit Message**
1. คลิกที่ช่อง **Summary** (ด้านล่างซ้าย)
2. พิมพ์คำอธิบายการเปลี่ยนแปลง เช่น:
   ```
   สร้างหน้าแรก - แนะนำตัวเอง
   ```
   
> **เคล็ดลับ Commit Message ที่ดี:**
> - สั้น กระชับ ไม่เกิน 50 ตัวอักษร
> - บอกว่า "ทำอะไร" เช่น "เพิ่ม", "แก้ไข", "ลบ"
> - ตัวอย่างดี: "เพิ่มส่วน contact information"
> - ตัวอย่างไม่ดี: "แก้โค้ด", "update"

**3.3 กด Commit!**
1. คลิกปุ่ม **"Commit to main"** (สีน้ำเงิน)
2. ถ้าสำเร็จ แถบ Changes จะว่างเปล่า

---

## ส่วนที่ 4: ดูประวัติการทำงาน (History)

1. คลิกที่แท็บ **"History"** (ด้านบน ข้างๆ "Changes")
2. จะเห็น Commit ที่เพิ่งทำปรากฏขึ้น
3. คลิกที่ Commit เพื่อดูรายละเอียดว่าไฟล์อะไรเปลี่ยนบ้าง

---

## ส่วนที่ 5: ฝึก Commit ครั้งที่ 2

**5.1 กลับไปแก้ไขไฟล์**
1. กลับมาที่ VS Code
2. เปิด Cline แล้วสั่ง:
   ```
   ช่วยเพิ่มส่วน "ปรัชญาการสอน" ในหน้าเว็บของฉัน 
   เป็นข้อความสั้นๆ 1-2 ประโยคที่บอกถึงความเชื่อในการสอน
   ```
3. รับ Approve ใน Cline
4. Refresh browser ดูผล

**5.2 Commit การแก้ไข**
1. กลับมาที่ GitHub Desktop
2. จะเห็น `index.html` ปรากฏใน Changes อีกครั้ง
3. เขียน Commit Message:
   ```
   เพิ่มส่วนปรัชญาการสอน
   ```
4. คลิก **"Commit to main"**

## ส่วนที่ 6: เข้าใจการทำงาน

```
แก้ไขไฟล์  →  ไฟล์ปรากฏใน "Changes"  →  เขียน Message  →  Commit
    ↑_________________________________________________|
                   วนซ้ำทุกครั้งที่ทำงาน
```

**คำถามสำหรับคิด:**
- ทำไมต้องเขียน Message? → เพื่อให้รู้ว่า Save นั้นๆ ทำอะไร เมื่อต้องย้อนกลับ
- ต้อง Commit บ่อยแค่ไหน? → ทุกครั้งที่ทำสิ่งหนึ่งสิ่งใดสำเร็จ (ไม่ใช่แค่ตอนจบ)
