# LAB-08 | แก้บัคด้วย AI และย้อนเวลากลับด้วย Git Desktop

**Session:** 2.4 | **เวลา:** 13:00 - 14:30 น. | **ระยะเวลา:** ~1 ชั่วโมง 30 นาที

> ผลลัพธ์: ผู้เรียนไม่กลัว Error อีกต่อไป และรู้วิธีกู้คืนโค้ดเมื่อเกิดปัญหา

---

## แนวคิดหลัก

```
Error ไม่ใช่ความล้มเหลว — มันคือข้อมูลที่บอกว่าอะไรผิดปกติ
```

นักพัฒนา (Developer) มืออาชีพเจอ Error ทุกวัน สิ่งที่แตกต่างคือ:
- ❌ มือใหม่: เห็น Error → ตกใจ → ไม่รู้จะทำอะไร
- ✅ มืออาชีพ: เห็น Error → อ่านข้อความ → หาสาเหตุ → แก้

**และตอนนี้เรามี AI ช่วยแก้ Error ได้แล้ว!**

---

## ส่วน A: แก้บัคด้วย AI

### A1: ทำความเข้าใจ Error Message

เมื่อเกิด Error จะมีข้อความปรากฏขึ้น สิ่งที่ต้องหาในข้อความ Error:

```
❶ ชื่อ Error      → บอกประเภทปัญหา
❷ ไฟล์และบรรทัด  → บอกว่าเกิดที่ไหน
❸ คำอธิบาย       → บอกว่าเกิดอะไรขึ้น
```

**ตัวอย่าง Error จริงๆ:**
```
Uncaught ReferenceError: feedbackList is not defined
    at displayFeedbacks (script.js:15)
    at script.js:5
```

อ่านได้ว่า:
- **ประเภท:** ReferenceError (ใช้ตัวแปรที่ไม่มีอยู่)
- **ที่ไหน:** ไฟล์ `script.js` บรรทัด 15
- **อะไร:** ตัวแปรชื่อ `feedbackList` ไม่ได้ถูกประกาศ

---

### A2: วิธีดู Error ใน Browser

เมื่อเว็บไม่ทำงานตามที่ควร:

1. คลิกขวาในหน้าเว็บ → เลือก **"Inspect"** หรือ **"ตรวจสอบ"**
2. คลิกแท็บ **"Console"**
3. Error จะแสดงเป็นข้อความสีแดง

---

### A3: ฝึกแก้ Error — แบบฝึกหัดจริง

**ขั้นตอนที่ 1: ทำให้เกิด Error โดยตั้งใจ**

เปิด Cline แล้วส่ง Prompt นี้ (เราจะให้ AI ทำโค้ดพังโดยตั้งใจ!):

```
ช่วยแก้ไขไฟล์ script.js ของ feedback-app โดย:
1. เปลี่ยนชื่อตัวแปร feedbackList เป็น feedbackContainer ในบางที่ (ไม่ใช่ทุกที่)
เพื่อทำให้เกิด ReferenceError โดยตั้งใจ สำหรับการฝึก debug
```

คลิก Approve

**ขั้นตอนที่ 2: ทดสอบว่าพังจริง**
1. เปิดเว็บใน Browser
2. เปิด Console (F12 → Console)
3. ควรเห็น Error สีแดง
4. Screenshot หรือจดจำข้อความ Error

**ขั้นตอนที่ 3: ให้ AI แก้ Error**

คัดลอกข้อความ Error ทั้งหมดจาก Console แล้วส่งใน Cline:

```
เว็บ feedback-app มี Error ดังนี้:
[วาง Error message ที่คัดลอกมาจาก Console ที่นี่]

ช่วยหาสาเหตุและแก้ไขให้หน่อย
```

คลิก Approve เพื่อให้ AI แก้ไขไฟล์

**ขั้นตอนที่ 4: ทดสอบว่าแก้ได้แล้ว**
1. Refresh Browser
2. ทดสอบส่ง Feedback
3. ควรทำงานได้ปกติ

---

### A4: เทคนิคการแก้ Error อย่างมีประสิทธิภาพ

**เทคนิค 1: Copy Error ทั้งหมด ไม่ตัดทอน**
- คัดลอก Error ทั้งหมดรวมถึงบรรทัดที่เกิดปัญหา
- ยิ่งให้ข้อมูลมาก AI ยิ่งแก้ได้แม่นยำ

**เทคนิค 2: บอก Context เพิ่มเติม**
```
เว็บ feedback-app มี Error ตอนที่กดปุ่มส่งความคิดเห็น:
[Error message]
ก่อนหน้านี้ผมเพิ่ง[ทำอะไร]ไป ช่วยดูด้วยว่าเกี่ยวข้องกันไหม
```

**เทคนิค 3: ถ้าแก้แล้วยัง Error**
```
แก้ตามที่บอกแล้วแต่ยังเจอ Error อีก:
[Error ใหม่]
ช่วยลองดูอีกครั้ง
```

## ส่วน B: ย้อนเวลากลับด้วย Git Desktop

### B1: สถานการณ์ที่ต้องใช้ Rollback

- AI เขียนโค้ดใหม่แล้วเว็บพังทั้งหน้า
- ลบอะไรที่สำคัญออกไปโดยไม่ตั้งใจ
- เพิ่มฟีเจอร์แล้วทำให้ฟีเจอร์เก่าเสีย
- ทดลองอะไรบางอย่างแล้วอยากกลับไปจุดก่อนหน้า

**สำคัญ: Rollback ทำได้เฉพาะไฟล์ที่ Commit ไว้แล้วเท่านั้น!**

> นี่คือเหตุผลที่เราต้อง Commit บ่อยๆ ระหว่างทำงาน

---

### B2: ฝึก Rollback — แบบฝึกหัดจริง

**ขั้นตอนที่ 1: Commit สถานะปัจจุบัน (จุดปลอดภัย)**
1. เปิด GitHub Desktop
2. ตรวจสอบว่าไม่มีการเปลี่ยนแปลงค้างอยู่ใน Changes
3. ถ้ามี ให้ Commit ก่อน:
   ```
   บันทึกสถานะก่อนทดสอบ rollback
   ```

**ขั้นตอนที่ 2: ทำโค้ดพังโดยตั้งใจ**

เปิด Cline แล้วส่ง Prompt:

```
ช่วยแก้ไขไฟล์ style.css ของ feedback-app โดย:
1. เปลี่ยนสีพื้นหลังทั้งหน้าเป็นสีดำสนิท
2. เปลี่ยนตัวอักษรทั้งหมดเป็นสีขาว
3. ทำให้ปุ่มหายไป (display: none)
นี่เป็นการทดสอบ rollback ครับ
```

คลิก Approve

**ขั้นตอนที่ 3: ดูผลลัพธ์**
1. Refresh Browser
2. เว็บควรดูแย่มาก (ตั้งใจให้เป็นแบบนั้น!)

**ขั้นตอนที่ 4: Commit สถานะที่พัง**
1. กลับมา GitHub Desktop
2. เขียน Commit Message:
   ```
   ทดสอบ: โค้ด CSS พัง (สำหรับฝึก rollback)
   ```
3. คลิก Commit

---

### B3: วิธี Rollback กลับไปก่อนหน้า

**วิธีที่ 1: Revert Commit (แนะนำ)**

1. เปิด GitHub Desktop
2. คลิกแท็บ **"History"**
3. เลือก Commit ที่ทำให้พัง (อันล่าสุด "ทดสอบ: โค้ด CSS พัง")
4. คลิกขวาที่ Commit นั้น
5. เลือก **"Revert Changes in Commit"**
6. GitHub Desktop จะสร้าง Commit ใหม่ที่ยกเลิกการเปลี่ยนแปลงนั้น
7. คลิก **Commit Revert**

**ผลที่ควรเห็น:**
- ใน History มี Commit ใหม่ชื่อ `Revert "ทดสอบ: โค้ด CSS พัง"`
- ไฟล์ CSS กลับมาเป็นปกติ
- Refresh Browser แล้วเว็บสวยเหมือนเดิม

---

**วิธีที่ 2: ยกเลิกการเปลี่ยนแปลงที่ยังไม่ได้ Commit**

ถ้าแก้ไขไฟล์แล้วยังไม่ได้ Commit:
1. เปิด GitHub Desktop
2. ใน **Changes** จะเห็นไฟล์ที่เปลี่ยน
3. คลิกขวาที่ไฟล์นั้น
4. เลือก **"Discard Changes"**
5. ยืนยันการยกเลิก

> ⚠️ ระวัง: วิธีนี้จะลบการเปลี่ยนแปลงถาวร ไม่สามารถ Undo ได้!

---

### B4: ทดสอบว่า Rollback สำเร็จ

1. เปิด Browser
2. Refresh หน้าเว็บ
3. ฟอร์มและดีไซน์ควรกลับมาปกติ
4. ทดสอบส่ง Feedback ว่าใช้งานได้

---

## สรุป: Loop การทำงานเมื่อเจอปัญหา

```
เจอ Error
    ↓
อ่าน Error message (อย่าตกใจ!)
    ↓
Copy Error → ส่งให้ AI ใน Cline
    ↓
AI แนะนำวิธีแก้ → Approve
    ↓
ทดสอบว่าแก้ได้แล้ว?
    ├─ ใช่ → Commit งาน ✅
    └─ ยัง → ส่ง Error ใหม่ให้ AI อีกครั้ง

ถ้า AI แก้แล้วยิ่งพัง → Rollback ด้วย Git Desktop
```
